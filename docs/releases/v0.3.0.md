# v0.3.0

本版本完成 Desktop Swarm、统一模型角色与 Provider 上下文管理，并系统改进了 Windows 命令环境、工具调用可靠性和设置体验。

## 升级说明

- `v0.2.5` 的 AppConfig v14 会自动迁移到 v24；已有 Provider、凭据引用、模型配置、权限和其余运行限制会保留。旧的全局 Run 与单次 Swarm Agent 数量配置会移除。SQLite 会从 v5 自动迁移到 v9，现有 Project、Session、消息和 Subagent 记录无需手工处理。
- Provider 模型目录刷新改为只追加新模型，不再删除或覆盖已有配置；手工添加的模型也会继续保留。
- 切换 Provider 或模型时，应用会用可移植的 conversation transcript 开启新的历史 epoch，避免把不兼容的 Provider continuation 或加密 reasoning 直接发送给新模型。
- 当前桌面安装包仍为未签名的 Windows x64 构建，升级时 Windows SmartScreen 可能显示提示。

## Agent、Swarm 与模型池

- 新增普通 `swarm_run` 工具。用户明确要求多 Agent 或并行调查时，主 Agent 可以把共享背景与多个独立任务交给模型池中的 child；每项任务显式选择只读工具或继承父 Run 权限，一次调用可启动多个任务和副本。
- Swarm 编排调用本身低风险并可并发执行；child 的写入、命令、网络等副作用仍按父 Run 的权限模式审批，并以可审计 Job 执行。
- Agents 侧栏升级为 Job → child 两级视图，可查看并行任务的状态、分配模型、耗时、工具数量、Token 使用和最终输出；hidden child Session 仍不会进入普通会话列表。
- 模型设置统一支持主模型与辅助模型角色，可分别配置 Provider、模型和思考深度；模型池只选择带能力标注的精确 route，不配置 Agent 数量或并发限制。
- 对话标题可使用轻量模型自动生成，失败时保留确定性的本地标题回退。

## Provider 与上下文管理

- 引入 Provider-anchored compaction：Provider 支持原生压缩时优先使用原生能力，不支持时回退到普通摘要压缩；失败会停止边界提交并允许用户重试。
- 新增 `compact_summary` 和 `conversation_transcript` 历史语义，用于保存 Provider 原始压缩结果以及跨 Provider/模型迁移所需的字面历史。
- 上下文上限不再由本地估算提前拒绝，最终请求是否超限交由 Provider 判定；本地估算继续用于规划、截断和界面提示。
- Anthropic Messages、Responses 与 Chat Completions 路径统一处理压缩回退、usage、reasoning 等级和模型覆盖。
- Auto 审批模型现在会收到当前工具的描述、参数 schema、effects 和默认风险；标签与文本均经过安全转义，无法安全编译时回退到人工审批。

## 工具与 Windows 命令环境

- `run_command.shell` 和交互 Terminal 统一使用用户配置的命令解释器。Windows 会自动发现 PowerShell 7、Windows PowerShell、CMD、Git Bash 和 Nushell，并在配置失效时安全回退。
- PowerShell 命令使用 UTF-8 输出设置；捕获层为不遵守 UTF-8 的程序保留系统代码页回退。
- Terminal ID 改为进程内递增整数，每个 Session 最多打开 16 个 Terminal；`terminal_send` 会自动提交输入，无需模型额外发送回车。
- 工具参数进入执行器前会删除多余字段并转换明确可兼容的标量类型，错误信息会指出具体字段；MCP 和未知工具仍保持保守边界。
- 扩充只读 Git 工具，`git_diff` 支持 revision/range，并增加分支、日志、状态和对象检查能力。
- 新增历史派生的 `todo_update` 清单。复杂任务可以在时间线中显示当前步骤，失败的 Todo 调用不会改变清单；它不等同于需要审阅的 Durable Plan。

## 设置、界面与稳定性

- Provider 设置支持自动保存、手工新增和删除模型；默认模型可从完整目录选择，而对话下拉框只展示用户启用的模型。
- 设置页新增 Project 管理列表和删除入口，并将应用、模型、网络、运行、安全、集成等配置拆分为独立状态域。
- 修复模型选择草稿被 Vue 响应式代理污染后触发 `structuredClone` 失败、Session 卡死的问题。
- 统一运行中状态展示，用户消息右对齐，默认输入焦点恢复 Naive UI 原生样式，并压缩标题区的 usage 信息。
- 日常 `npm run check` 并行执行 lint、格式、类型和确定性单测；完整 `npm run verify` 保留 runtime、打包、SQLite 和 Electron E2E 发布门禁。
- 修复并发 trace 清理竞态、会话标题覆盖、Shell 配置回退、终端生命周期以及多个 compaction/fork/rewind 边界问题。

## 已知限制

- Swarm child 仍为自包含任务，没有递归委派、继续追问或 Agent 间通信能力；主 Agent 可以选择只读工具或继承自身权限，继承模式下的副作用继续逐次审批。
- Swarm 尚未提供 Job 取消按钮、压力场景下的完整费用汇总或远程 Worker；这些属于后续 hardening。
- Todo 是从前端当前已加载的历史消息尽力重建的辅助状态；更新位于更早分页、被压缩或无法解析时可能不显示，不影响 Agent 继续执行。
- 自定义 Shell profile、版本探测和 WSL adapter 尚未实现。
- ProjectModel、Serena 和 `project_*` / `code_*` 工具仍保持关闭，等待迁移到 SQLite 后重新启用。
